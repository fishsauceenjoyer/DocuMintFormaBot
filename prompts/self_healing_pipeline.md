# 🧠 Роль: AI DevOps & QA self-Healing Agent

Ты выступаешь в роли Senior DevOps/QA инженера. Наша автоматическая система контроля качества (GitHub Actions Quality Gates) упала с ошибкой. Твоя цель — проанализировать лог падения, локализовать баг и безопасно исправить его по правилам STRICT AI GIT FLOW.

## 📥 ВХОДНЫЕ ДАННЫЕ ДЛЯ АНАЛИЗА:
- Лог ошибки из интерфейса CI/CD (например, ошибки mypy, black, flake8 или bandit).
- Текущая активная ветка.

## 🛠️ АЛГОРИТМ ТВОИХ ДЕЙСТВИЙ (EXECUTION RULES):
1. **Изоляция (Git Flow):** Убедись, что ты находишься в изолированной фича-ветке (например, `feat/fix-...` или `chore/fix-...`). Пуш напрямую в main категорически ЗАПРЕЩЕН.
2. **Анализ лога:** Внимательно прочитай файл и строку, на которую указал линтер или типизатор. Не гадай — открой этот файл через `read_file` и изучи контекст.
3. **Исправление ошибок:**
   - **Mypy (Типы):** Если типы несовместимы, примени явное приведение типов (например, `bool()`, `int()`, `str()`) или обнови аннотации типов в сигнатуре функций.
   - **Black/Flake8 (Стиль):** Запусти локальное автоформатирование `uv run black <путь_к_файлу>`. Не пытайся править пробелы вручную.
   - **Bandit (Безопасность):** Если уязвимость ложная (false positive) в утилитах автоматизации — подави её через инлайн-маркер `# nosec`. Если реальная — перепиши небезопасный код.
4. **Локальный контроль:** Перед отправкой кода ОБЯЗАТЕЛЬНО запусти проверку локально: `uv run mypy .` или `uv run python scripts/run_mutations.py`.
5. **Фиксация без спама:** Закоммить изменения коротким сообщением (например, `fix(types): resolve mypy compliance in scripts`) и сделай пуш: `git push origin HEAD`.

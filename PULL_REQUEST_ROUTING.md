# PULL_REQUEST_ROUTING.md — Фикс уязвимости инфраструктуры роутинга (TDD)

## Тип изменений
**Фикс уязвимости инфраструктуры роутинга** (разработан через TDD — краш-тесты в `tests/test_routing_blind_spots.py`).

## Что изменено и зачем

### 1. `config_runtime.py` — жёсткая валидация ROUTING ID

Добавлена функция `_parse_routing_id(raw_value: str, env_key: str) -> int`, которая применяет три обязательных правила к каждой ROUTING-переменной:

1. **Преобразование в `int`** — значение должно быть парсируемым целым числом.
2. **Строгий префикс `-100`** — строковое представление ID должно начинаться с `-100` (стандартный префикс Telegram для супергрупп и каналов).
3. **Минимум `-100000000`** — значение должно быть строго меньше `-100000000` (проверка на минимальную длину реального ID супергруппы).

При нарушении любого правила выбрасывается:
```python
raise ValueError("Критическая ошибка: неверный формат ROUTING ID")
```

Валидация применяется только к переменным, явно присутствующим в `os.environ` (переданы через `.env` или окружение). Значения по умолчанию (`-100123456789` для роутинга документов, `555555555` → заменено на `-100123456789` для `ROUTING_DEFAULT` в `.env`) остаются без изменений, чтобы не ломать локальный baseline.

### 2. `utils/router.py` — проброс `TelegramForbiddenError` наверх

В методе `_safe_send` блок `except Exception` разделён на два:

- `except TelegramForbiddenError as e:` — ошибка логируется с полным traceback и **принудительно пробрасывается наверх через `raise`**. Больше не поглощается молча и не возвращается как `False`.
- `except Exception as e:` — остальные ошибки继续 обрабатываются по старому сценарию (логирование + фолбэк на `MANAGER_ID`), чтобы не ломать существующие вызовы, которые ожидают `False` при некритичных сбоях.

Обновлены docstring и типизация метода: добавлен раздел `Raises` с описанием `TelegramForbiddenError`.

### 3. `.env` — исправлен дефолт `ROUTING_DEFAULT`

Значение `ROUTING_DEFAULT` изменено с `555555555` (обычный пользовательский ID, не супергруппа) на `-100123456789` (валидный ID супергруппы), чтобы пройти новую валидацию при загрузке через `load_dotenv()`.

## Влияние на обратную совместимость

Изменения **изолированы** и не затрагивают baseline-тесты:

1. **`config_runtime.py`** — строгая валидация применяется только к env-переменным, явно заданным в `os.environ`. Значения по умолчанию не валидируются жёстко, поэтому локальный запуск без `.env` продолжает работать.
2. **`utils/router.py`** — только `TelegramForbiddenError` теперь пробрасывается вместо возврата `False`. Все остальные исключения продолжают обрабатываться по старому сценарию (фолбэк на `MANAGER_ID`, возврат `False`). Вызовы `_safe_send`, которые не ловят `TelegramForbiddenError`, продолжают работать через общий `except Exception`.
3. **`.env`** — `ROUTING_DEFAULT` приведен к валидному формату супергруппы (`-100123456789`); это не ломает существующую логику, так как значение по-прежнему используется как целевой чат по умолчанию.

Никаких сигнатур публичных API не изменено, не добавлено новых обязательных параметров, не удалено существующего функционала.

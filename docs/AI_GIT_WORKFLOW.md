# 🤖 AI Git Workflow — Регламент ветвления для ИИ-агентов

> **Цель:** предотвратить засорение истории микро-PR и перегрузку CI/CD пайплайнов.
> ИИ-агенты генерируют код быстро, поэтому мы вводим **пакетные релизы** — все изменения
> накапливаются в одной долгоживущей ветке и попадают в `main` одним аккуратным коммитом.

---

## 1. 🚫 Запрет микро-PR в main

**Любая комплексная задача** (рефакторинг, добавление фичи, исправление бага, обновление
инфраструктуры) **должна выполняться в ОДНОЙ долгоживущей ветке**.

| Тип задачи | Префикс ветки | Пример |
|------------|---------------|--------|
| Новая функциональность | `feature/` | `feature/payment-methods-rename` |
| Технический долг / инфраструктура | `chore/` | `chore/ai-infrastructure-upgrade` |
| Исправление бага | `fix/` | `fix/order-tracking-null` |
| Документация | `docs/` | `docs/api-usage-guide` |

**Запрещено:**
- ❌ Открывать PR в `main` на каждую мелкую правку.
- ❌ Создавать ветки вида `micro/...` и мерджить их напрямую в `main`.
- ❌ Пулл-реквесты с одним-двумя файлами, если они являются частью более крупной задачи.

**Разрешено:**
- ✅ Одна ветка = одна задача = один финальный PR.

---

## 2. 🧱 Атомарные коммиты внутри ветки

Внутри долгоживущей ветки ИИ **имеет право** делать частые микро-коммиты.
Это нормально и даже приветствуется — история внутри ветки может быть подробной.

### Стандартные префиксы коммитов

| Префикс | Назначение |
|---------|------------|
| `feat:` | Новая функциональность |
| `fix:` | Исправление бага |
| `docs:` | Документация |
| `test:` | Тесты |
| `refactor:` | Рефакторинг без изменения поведения |
| `chore:` | Обслуживание, зависимости, инфраструктура |
| `style:` | Форматирование, линтеры |
| `perf:` | Оптимизация производительности |

### Примеры

```bash
# ✅ Хорошо — атомарные коммиты с понятными префиксами
git commit -m "feat: add payment method rename endpoint"
git commit -m "fix: handle null tracking number in order serializer"
git commit -m "test: cover payment rename edge cases"
git commit -m "docs: update API reference for rename endpoint"

# ❌ Плохо — неинформативные сообщения
git commit -m "update"
git commit -m "fix stuff"
git commit -m "wip"
```

## 3. 🎯 Единый финальный PR

PR в ветку `main` открывается **только ОДИН раз** — когда:

1. ✅ Весь сценарий автоматизации полностью завершен.
2. ✅ Все локальные тесты горят зеленым (`uv run pytest`).
3. ✅ Линтеры и статический анализ чистые (`uv run black --check .`, `uv run flake8 .`, `uv run mypy`).
4. ✅ Аудит безопасности пройден (`uv run bandit`).
5. ✅ Ветка синхронизирована с актуальным `main` (нет конфликтов).

### Чек-лист перед открытием PR

```markdown
- [ ] Все микро-коммиты собраны в один squash-коммит (автоматически через CI)
- [ ] Тесты проходят локально
- [ ] Линтеры чистые
- [ ] Нет конфликтов с main
- [ ] Описание PR содержит сводку всех изменений
```

### Как это работает на практике

```
main ────────────────────────────────────────────────► (squash merge)
       \                                            /
        feature/payment-methods-rename ────────────┘
         ├─ feat: add endpoint
         ├─ fix: handle null
         ├─ test: cover edge cases
         └─ docs: update reference
```

Все микро-коммиты из ветки `feature/...` при мердже в `main` объединяются
в **один аккуратный коммит** (Squash and Merge) — история `main` остаётся чистой.

## 4. 🔄 Пакетный сбор микро-веток (опционально)

Если по какой-то причине были созданы ветки с префиксом `micro/`, их можно
автоматически собрать в одну целевую ветку `feature/combined-release`:

```bash
uv run python utils/merge_micro_branches.py            # выполнить сборку
uv run python utils/merge_micro_branches.py --dry-run  # показать план без изменений
uv run python utils/merge_micro_branches.py --target feature/my-release  # своя ветка
```

Скрипт:
1. Находит все локальные ветки `micro/*`.
2. Сливает их содержимое в целевую ветку через `git merge --squash`.
3. Удаляет отработавшие микро-ветки.

---

## 5. 📌 Сводка правил

| Правило | Описание |
|---------|----------|
| **Одна задача = одна ветка** | `feature/`, `chore/`, `fix/`, `docs/` |
| **Микро-коммиты разрешены** | Внутри ветки, с префиксами `feat:`, `fix:`, `test:` и т.д. |
| **Один финальный PR** | Только когда всё готово и тесты зелёные |
| **Squash and Merge** | CI принудительно объединяет микро-коммиты в один |
| **Микро-ветки** | Собираются скриптом `utils/merge_micro_branches.py` |
